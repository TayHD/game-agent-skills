# Creature AI on State Trees

## Settings the project supplies

| Setting | Meaning |
|---|---|
| `FEEL_TARGETS` | The measured design targets (tells, punish windows, detection times, stops, turns, cost). |
| `ROLES` | The behaviour roles (for example apex predator, pack hunter, ambusher, grazer, herd defender, scavenger, swarm). |
| `SPECIES_DATA` | The per-species data asset with traits and tuning. |
| `LAB` | The lab map, spawn and trace commands, and the trace analyser. |
| `SANITY_CHECK` | The whole-creature sanity command run before anything is called ready. |
| `BUDGETS` | Server AI and client animation cost budgets at full player count. |

## Architecture

- **Layers, in order:** senses (sight cone and trace, hearing) then belief (threat, last seen, memory) then awareness (unaware, suspicious, alert, engaged) then selection, then presentation.
- **Think cadence** is owned by the controller (faster when active, slower when observed or dormant); the tree component never ticks itself.
- **Selection is pure:** one function holds the branch priority order and runs before the tree ticks; the tree has one state per branch with one enter condition and one exit.
- **One tree per role,** generated by code so trees stay consistent.
- **Presentation channel:** the server fills one replicated intent struct in one place; one-shot events go through unreliable multicasts; clients only read. Dedicated servers never animate.
- **Species identity is data:** every species-specific gate reads a trait or the role from `SPECIES_DATA`, never a species name in code.
- **Server authority:** every decision, perception and damage change stays on the server; a client value never feeds a decision. Logic in C++, tuning in data, Blueprints for cosmetics only.

## Feel pillars (check each change against those it touches)

Weight and momentum; intent readable before it happens (stages with posture, head, gait and call; every dangerous attack has a measured tell and a punish window); creatures have their own lives; species personality; predators hunt rather than chase (notice, assess, stalk, commit, then search when they lose you); fair, dodgeable, changing combat (attack tokens stop dog-piling); groups behave as groups; one food chain with humans and players; bounded cost.

## Method

1. Write the change against `FEEL_TARGETS`; every claim in a report is a row: target, measured, pass.
2. Tuning values are live knobs (console variables or species data), never hard-coded constants, so tries run in a persistent lab session without rebuilds.
3. Explore fast in `LAB`, then land once through a gated hold.
4. Measure with the trace analyser on lab courses (pursuit, pivot, stealth, pen and herd), not by opinion.
5. Before saying it works: run `SANITY_CHECK` and read every row, check the whole creature against its design (stale data from an older system, which graph actually runs, facing and clip coverage), and watch a capture of the real behaviour.

## Adding a species to an existing system

Probe the rig first; export and import with copies of the proven scripts; install with a bone map, clip table and physics radii from the export; point the spawner at the new kit and keep the old one untouched for before-and-after rows; hold with labs before and after on the same build. List every hard-coded first-species name in tools as a gap before starting.

## Done when

The behaviour meets the measured targets on lab traces, stays within `BUDGETS`, passes `SANITY_CHECK`, and a capture of the real behaviour shows it.
